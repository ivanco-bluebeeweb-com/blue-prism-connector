# Blue Prism Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
RPA-оператор/администратор Blue Prism Enterprise, обычно в крупной регулируемой отрасли
(банки, страхование), где Blue Prism ценят за строгий контроль доступа и аудит.

## 2. Момент истины после подключения
Сразу после `connect_blue_prism` — сводка по ресурсам (runtime resources) и очередям
работы: сколько ресурсов онлайн, сколько элементов очереди ожидает/упало.

## 3. Что пользователь видит
- Процессы (опубликованные автоматизации) — `list_processes`.
- Ресурсы (машины-исполнители) и их статус — `list_resources`.
- Очереди работы (work queues) и их элементы — `list_work_queues`, `list_queue_items`.
- Сессии выполнения процесса с логами — `list_sessions`, `get_session_log`.
- Расписания — `list_schedules`.
- Учётные данные (Credential Manager, без значений) — `list_credentials`.
- Пользователей и роли (важно для регулируемых отраслей — аудит доступа) —
  `list_users`, `list_roles`.

## 4. Чем пользователь может управлять
- Запускать процесс на конкретном ресурсе — `start_session`.
- Останавливать выполняющуюся сессию — `stop_session`.
- Добавлять элемент в очередь работы — `create_queue_item`.
- Помечать элемент очереди как выполненный/для повтора — `update_queue_item_status`.
- Создавать/приостанавливать расписание — `create_schedule`, `pause_schedule`.
- Управлять правами доступа пользователя (важно для compliance-отчётности) —
  `assign_role`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'какие элементы очереди сверки транзакций упали сегодня?'. Она
находит через `list_queue_items`, а я прошу пересчитать их — `update_queue_item_status`
возвращает их в очередь для повторной обработки, с полным аудиторским следом."

## 6. Что делает это "заточенным под него"
`list_roles`/`assign_role` работают с РЕАЛЬНОЙ ролевой моделью доступа именно этого
Blue Prism окружения — критично для банков/страховых, где это требование комплаенса.
